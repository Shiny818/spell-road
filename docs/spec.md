## 1. コンセプト

- **魔法カードで駆け引きをする、ファンタジーのすごろく**。プレイヤーは見習い魔法使いになり、魔法のカード（スペルカード）を使い分けてゴールを目指す。
- 止まったマスで起きるのは「カードの入手・交換」など補助的なことだけ。勝敗に関わる効果は、**手札のカードをいつ使うか**というプレイヤーの判断で決まる。
- 最大4人プレイ。
- モードは2つ:
  - **1人プレイ（ステージモード）**: CPUと対戦し、クリア報酬で成長していく継続型。
  - **マルチプレイ（対戦モード）**: 各自の端末で通信対戦する。1ゲームで完結し、次のゲームへは何も引き継がない。

## 2. 基本ルール

### 2.1 プレイ人数・勝利条件
| 項目 | 内容 |
|---|---|
| 人数 | 2〜4人（1人プレイでは自分＋CPU 1〜3人） |
| 1位 | 最初にゴールマスに到達したプレイヤー |
| 2位以降 | 【決定】1位がゴールした時点でゲーム終了。ゴールまでの残りマス数が少ない順に順位を決める |
| ゴール判定 | 【決定】出目がゴールまでの残りより多くてもゴールになる |
| ダイス | 6面ダイス1個（カードで2個振りや出目の変更あり） |

**残りマス数の数え方**
- 分岐で道が分かれていてルートによって長さが違う場合は、**今いるマスからゴールまでの最短の距離**で数える。
- まだ分岐の前にいる場合も、最短ルートで数える。
- 【決定】残りマス数が同じときは**同じ順位**にする（例: 2位が2人なら、その次は4位）。

### 2.2 ターンの流れ

```
[自分のターン]
 1. ターン開始       … カードを使える（例: ダイス2個振り、相手を1回休み）
 2. ダイスを振る
 3. 出目が出た後     … カードを使える（例: 出目+1、振り直し）
 4. 移動             … 出目の分だけ進む（関所では止まる）
 5. マスの効果       … 止まったマスの効果が起きる（カード入手・交換・コイン）
 6. ターン終了       … カードを使える／手札が上限を超えた分を捨てる

[他人のターン中]
 ・カウンターカードだけ使える（例: 自分への妨害を打ち消す）
```

- 【決定】**自分のターンに使えるカードは1枚まで**。1〜6のうち、どのタイミングで使うかを選ぶ。
- 【決定】**カウンターカードは別枠**。他人のターン中に使っても、自分のターンの1枚にはカウントしない。
- 【決定】カウンターは**手札にある限り何回でも使える**。
  - 例: Aがカウンターを2枚持っていて、BとCがそれぞれAを攻撃した場合、Aは1枚ずつ使って両方を防げる。
  - 【決定】カウンターは攻撃1回につき1枚。1回の攻撃にカウンターを2枚重ねることはできない。
- 【決定】**カウンターにカウンターはできない**。例えば、Aが「反射の鏡」で攻撃をはね返したとき、攻撃したBはそれをさらにカウンターで防げない。何回もはね返し合うと、処理も画面も分かりにくくなるため。
- カウンターを使うかどうかの確認は、妨害の対象になったプレイヤーにだけ表示する。確認には制限時間をつける（例: 10秒）。時間が過ぎたら「使わない」とみなす（通信対戦で1人が止まって全員が待つことを防ぐため）。

### 2.3 手札
| 項目 | 推奨値 |
|---|---|
| 初期手札 | 2枚 |
| 手札上限 | 5枚（超えた分はターン終了時に選んで捨てる） |
| 公開・非公開 | 枚数は公開、中身は非公開 |

## 3. マスの種類

| マス | 効果 | 備考 |
|---|---|---|
| **スタート** | 全員がここから始める | — |
| **何もなし** | 何も起きない | — |
| **カード入手** | 山札からカードを1枚引く | 手札が上限のときは、引いてから1枚捨てる |
| **カード交換** | 山札から3枚めくり、その中から1枚選んで手札の1枚と交換する。交換しないことも選べる | 手札がなければ何も起きない。選ばなかったカードは山札の一番下に戻す |
| **関所（強制ストップ）** | 下の「3.1」を参照 | チェックポイント、分岐の起点を兼ねる |
| **コイン** | コインを入手する（例: 1〜3枚） | 1人プレイだけ。マルチプレイでは「何もなし」になる（【提案】） |
| **ゴール** | 到達したらゴール | — |

### 3.1 関所（封印の扉）

**見た目と設定**: 関所は**魔法で封印された扉**。ダイスを振ることは「封印に魔力をぶつける」ことを表す。

1. **通過しようとしても必ずそこで止まる**（出目が余っていても移動を終える）。
2. 次のターンからダイスを振り、**条件に合う目**が出たら封印が解けて先に進める。
3. 【決定】抜けるときは、**出目に関係なく1マスだけ**進む。
4. 【決定】**分岐の起点**の場合は、**抜けたときの出目でルートが決まる**。
   - 例: 条件「4以上」 → 4・5なら森ルート、6なら山ルート
   - 出やすい目のルートは「遠回りだが安全」、出にくい目のルートは「近道でカードマスも多い」のように差をつける。
5. 【決定】**関所は必ずダイスを振って抜ける**。
   - 出目を操作するカード（出目±1、振り直しなど）は、条件判定と分岐の判定に使える。これで、狙ったルートに進むこともできる。
   - 「+3マス進む」のような移動カードは、関所にいる間は使えない。
   - 【決定】「ダイス2個振り」は、関所にいる間は使えない。
6. **チェックポイント**: 一度通過した関所より前には、カードの効果でも戻されない。「◯マス戻る」は、通過した関所の1つ先のマスで止まる。

#### 救済ルール「封印のひび」【決定: 3回失敗で抜けられる】
- 失敗するたびに、扉の封印に**ひびが1本入る**（扉の絵にひびが増えていく）。
- **ひびが3本入ると、次のターンの開始時に封印が砕ける**。そのターンは条件判定なしで抜けられる。
- 分岐の起点の場合、封印が砕けたターンにも**ダイスを振って**ルートを決める（出目の操作カードも使える）。
- ひびは、その関所を抜けたときにリセットされる（次の関所は0本から）。
- 意味付け: 失敗しても無駄にはならず、「あと1回で砕ける」という期待が生まれる。画面では、ひびの本数を常に表示する。

> 別案（参考）: 失敗するたびに条件が少しずつ緩む（例: 「6のみ」→「5以上」→「4以上」→ 必ず抜けられる）。こちらも理由付けとしては自然だが、分岐の出目との関係が複雑になるため、上の「封印のひび」を推奨する。

## 4. カード（スペルカード）— 大まかな方針

詳細なカードリストとカードの共通ルールは [cards.md](cards.md) を参照。ここでは方針だけを書く。

### 4.1 カードの属性
```
id, 名前, 説明文, 魔法の属性(下表), レア度(★1〜★3), コスト,
使えるタイミング(ターン開始 / 出目が出た後 / ターン終了 / カウンター),
対象(自分 / 相手1人 / 全員 / マス), 効果パラメータ
```

### 4.2 魔法の属性（6種類）【決定】

| 属性 | 色 | 効果の傾向 | カードの例 |
|---|---|---|---|
| **風** | 緑 | 自分の移動・位置の操作 | 「追い風（+3マス）」「疾風（ダイス2個振り）」「つむじ風（1つ前の人と位置を入れ替える）」 |
| **時** | 紫 | 出目の操作 | 「巻き戻し（振り直し）」「運命の針（出目±1）」「星読み（出目を好きな数にする／★3）」 |
| **炎** | 赤 | 相手を戻す・マスに罠を置く | 「火炎（相手を4マス戻す）」「炎の魔法陣（マスに罠を置く。踏んだ人は3マス戻る）」 |
| **氷** | 水色 | 相手の動きを止める・遅くする | 「氷結（相手を1回休み）」「凍てつく床（マスに罠を置く。踏んだ人はそこで移動が止まる）」「霜の呪い（相手の次の出目-2）」 |
| **光** | 黄 | 防御・カウンター・回復 | 「光の壁（妨害を1回無効）」「反射の鏡（妨害をはね返す）」「祝福（カードを2枚引く）」 |
| **闇** | 黒 | 手札への干渉 | 「盗みの影（相手の手札を1枚奪う）」「忘却（相手の手札を1枚捨てさせる）」 |

- 戻す効果はチェックポイントで止まる（3.1の6）。
- 位置を入れ替える効果は、入れ替えるとチェックポイントより前に戻る相手には使えない。
- 罠は、置いた本人が踏んでも発動する（【提案】）。罠は1回発動すると消える。

## 5. 1人プレイ（ステージモード）

### 5.1 構成
| 項目 | 案 |
|---|---|
| 構成 | ワールド → ステージ（例: 3ワールド × 5ステージ）。ワールドごとにテーマ（森、雪山、魔法学院の塔など）があり、ボードとCPUの数・強さが変わる |
| クリア条件 | 基本は1位でゴール。ステージによって「3位以内」「炎の魔法を3回使う」などの条件を変える |
| CPU | ライバルの魔法使いキャラクター。CPUごとに専用のデッキを持つ（例: 炎が得意なライバル）。強さは3段階: 弱=ランダムに使う／普通=簡単な判断（先頭の相手を妨害、ゴール前で加速）／強=有利になる見込みが高い手を選ぶ |
| セーブ | ブラウザの保存領域（localStorage）。【提案】バックアップ用に「セーブデータを書き出す・読み込む」機能もつける |

### 5.2 カードプールと魔導書（デッキ）【決定】
- 手に入れたカードは**カードプール**（コレクション）に入る。
- ステージを始める前に、カードプールから**魔導書（デッキ）**を組む。すごろくのカード入手・交換マスでは、この魔導書から作った山札のカードが出る。
- 【決定】数値は次のたたき台で進め、テストプレイで調整する:

| 項目 | 値 |
|---|---|
| 魔導書の枚数 | ちょうど20枚 |
| 同じカードの上限 | 3枚まで |
| コスト | ★1 = 1、★2 = 2、★3 = 4 |
| コスト上限 | 30から始まり、ワールドを進めると上がる（例: 30 → 35 → 40） |

- 山札: ゲーム開始時に魔導書をシャッフルして山札にする。山札がなくなったら、捨て札をシャッフルして山札に戻す。
- ステージによっては「コスト上限25」「氷属性禁止」などの特別ルールをつけることもできる。

### 5.3 コインとショップ【決定】
- コインは、**すごろくの中のコインマス**と、**クリア報酬**（順位に応じたボーナス）で手に入る。
- ショップは**ステージを選ぶ画面**にあり、コインで次のものを買える:
  - 新しいカード（カードプールに追加）
  - 【提案】着せ替え（キャラクターの帽子・杖など、見た目だけ）
- 【提案】ステージに負けてもコインは手に入れられる。負けても少しずつ前に進めるようにするため。

## 6. マルチプレイ（通信対戦）【決定: 最初から通信対戦】

### 6.1 遊び方
1. 1人が「部屋を作る」と、**部屋コード**（例: 4〜6文字）が表示される。
2. 他の人は、自分のスマホやPCで同じURLを開き、部屋コードを入力して参加する。
3. 部屋を作った人（ホスト）が人数を確認し、足りない分をCPUで埋めてゲームを開始する。

| 項目 | 内容 |
|---|---|
| 端末 | **1人1台**（スマホ・PC）。自分の手札は自分の端末にだけ表示される |
| CPUの参加 | ホストの端末でCPUの思考を動かす |
| カード | 全カードを使う共通の山札（1ゲームで終わるため、全員同じ条件） |
| ルール設定 | ホストが手札上限・ボードを選ぶ |

### 6.2 技術の方式: PeerJS（WebRTC）
- **最初の接続だけ**、PeerJSの無料の公開仲介サーバーを使い、その後は端末どうしで直接通信する。自分でサーバーを用意する必要はない。
- **ホストが親**: ゲームのルールの処理とダイスの結果の決定は、ホストの端末だけが行う。他の端末は「カードを使う」などの操作をホストに送り、ホストから結果を受け取る。
  - 不正（ダイスの結果をごまかすなど）がしにくい
  - 手札は持ち主にだけ送るので、他人の手札が見えない
- 1人プレイも、同じ仕組みを**通信なし**（自分の端末がホスト、他はCPU）で動かす。コードを1本にできる。

### 6.3 通信対戦で必要な処理
| 項目 | 対応 |
|---|---|
| 途中で切断した参加者 | 同じ部屋コードで再接続すると、続きから参加できる。戻ってこない間は、CPUが代わりに操作する |
| ホストが切断した場合 | ゲームを続けられない（ホストに全ての状態があるため）。【提案】ホストの端末に状態を自動保存し、ホストが部屋を作り直せば再開できるようにする（第2段階） |
| 操作の制限時間 | 手番の操作とカウンターの確認に制限時間をつける（2.2を参照） |
| インターネット | 必要（最初の接続で公開仲介サーバーを使うため） |
| 公開仲介サーバーが不安定な場合 | 自分で仲介サーバーを立てる方法もある（無料の範囲で可能）。必要になったら検討する |

### 6.4 開発中の動作確認
- 1台のPCでブラウザのタブを複数開けば、1人で通信対戦の動作確認ができる。

## 7. 技術【決定: ブラウザ】

- **TypeScript + Vite**
- 描画: 【提案】**Phaser 3**（2Dゲームエンジン）でボード・コマ・演出を作り、手札・メニューなどのUIはHTML/CSSで作る。
- **スマホでの操作を前提**にする（1人1台のため）。縦向きの画面を基本とし、PCでも遊べるようにする。
- 通信: PeerJS
- ゲームのルール（状態・ターン進行・カード効果）は**描画から切り離して作る**:
  - 状態は「操作（アクション）を順番に適用して変わる」形にする
  - 自動テストが書ける
  - CPUの思考と通信対戦で、同じコードを使える
- ボード・カード・ステージは**JSONのデータ**として定義する（コードを変えずに追加できる）。ボードは、分岐を表現できるように「マス（ノード）とその次のマスへのつながり」で表す。分岐のつながりには、どの出目でそのルートに進むかを持たせる。
- 配布: GitHub Pagesで公開して、URLを共有する。

### 7.1 フォルダ構成（予定）
```
Sugoroku/
├─ docs/            仕様書・素材のプロンプト集
├─ src/
│  ├─ core/         ゲームのルール（描画に依存しない）
│  ├─ ai/           CPUの思考
│  ├─ net/          通信対戦（PeerJS）
│  ├─ scenes/       Phaserの画面
│  ├─ ui/           HTML/CSSのUI
│  └─ data/         ボード・カード・ステージのJSON
├─ public/assets/   画像・音
└─ tests/
```

## 8. 素材の用意

### 8.1 方針
| 素材 | 方針 |
|---|---|
| ボード・マス・UI・カードの枠 | Claudeがコード（SVG/CSS）で描く。カードの枠は属性ごとに色を変える |
| **キャラクター・カードのイラスト** | **画像生成AI**で作る。下の共通プロンプトで絵柄をそろえる |
| アイコン | フリー素材（game-icons.net など。ライセンス表記が必要なものは、クレジット画面に記載する） |
| 効果音・BGM | フリー素材（効果音ラボ、魔王魂など）。利用規約を確認する |
| 仮素材 | 開発中は絵文字や図形で代わりにする。**素材がなくても開発を進められる**ようにする |

### 8.2 画像生成の共通プロンプト（たたき台）
```
cute chibi fantasy style, soft pastel colors, thick clean outlines,
simple flat shading, storybook illustration, white background,
(個別の内容: 例 "a small apprentice witch casting a fireball spell")
```
- キャラクター: 2〜2.5頭身の見習い魔法使い4人（プレイヤーのコマ）＋ライバルのキャラクター
- カードのイラスト: 魔法のエフェクトを中心にした絵。属性の色をはっきり使う
- 関所: 封印された扉（ひび0〜3本の4段階の絵）
- 実際の素材を作る前に、試しに何枚か生成して、絵柄を確定させる。使ったサービス・プロンプトは `docs/assets-prompts/` に記録する

## 9. 開発の段階（案）

> **MVP**（Minimum Viable Product）: 「遊べる最小限の試作版」のこと。見た目や機能を最小限にして、まず「遊んで面白いか」を確かめるための版。このプロジェクトでは、下の1〜3（ボード1つ・カード15種類・仮素材で、通信対戦まで遊べる状態）をMVPとする。

1. **ルールの中心部分**: ゲームのルール（`core/`）と自動テスト。画面なしで、CPUどうしの対戦を最後まで動かせる状態にする
2. **画面**: ボード1つ（分岐・関所あり）・カード15種類（cards.md 4.3）・仮素材で、1台で（CPU相手に）遊べる状態にする
3. **通信対戦**: PeerJSで部屋コード方式の対戦。切断・再接続の処理も含む
4. **調整**: 実際に遊んで、カードのバランスやボードの長さを調整する
5. **1人プレイ**: ステージ・コイン・ショップ・カードプール・魔導書の編集・セーブ・CPUの強さ3段階
6. **見た目**: 生成した素材への差し替え、アニメーション、音

> 2の「1台でCPU相手に遊べる状態」は、1人プレイモードの土台にもなる。

## 10. ボードの規模（プレイ時間からの見積もり）

【決定】プレイ時間は**4人で15〜20分**。ここから、ボードの長さを次のように見積もる（テストプレイで調整する）。

| 項目 | 見積もり |
|---|---|
| 1人の手番にかかる時間 | 20〜30秒（ダイス・移動の演出、カードを使うかどうかの判断を含む） |
| 1ラウンド（4人） | 約1.5〜2分 |
| 1ゲームのラウンド数 | **約10ラウンド** |
| 1ターンに進むマス数 | 平均3.5マス（ダイス）＋カードでの加速 − 妨害・休み ≒ 平均3マス前後 |
| 関所で止まるターン数 | 1つの関所で平均1〜2ターン（条件による） |
| **ボードの長さ（最短ルート）** | **約30〜35マス** |
| **関所の数** | **2〜3個**（そのうち1〜2個が分岐の起点） |

- 遠回りのルートは、最短ルートより3〜6マス長くする目安。
- 関所で分かれた道は、ゴールの数マス手前で合流させる（ゴールの場所が分かりやすいように）。関所を出てすぐゴール、にはしない。
- テストプレイの結果: 最短30マスでは短く感じたため、はじまりの森は**最短39マス**（CPU同士のシミュレーションで平均約14ラウンド）にした。
- 1人プレイのステージは、序盤のステージを短め（約20マス・関所1個）にして、後半ほど長くする。
- 各マスの割合の目安: カード入手 30%、カード交換 15%、何もなし 45%、コイン 10%（マルチプレイではコインマスは何もなし扱い）。
