# スペル・ロード ～カードで駆け引き！魔法すごろく～

魔法カードで駆け引きをする、ファンタジーのすごろくゲーム（ブラウザゲーム）。

- 仕様書: [docs/spec.md](docs/spec.md)
- カードリスト: [docs/cards.md](docs/cards.md)
- 素材リスト: [docs/assets.md](docs/assets.md)

## テストプレイ

`testplay.bat` をダブルクリックすると、開発用サーバーが起動してブラウザでゲームが開きます（http://localhost:5180）。
初回は必要なパッケージを自動でインストールします。終了するときは黒いウィンドウを閉じてください。

### スマホで遊ぶ

PCと同じWi-Fiにつないだスマホで遊べます。

1. `testplay-phone.bat` をダブルクリックする（`testplay.bat` で起動中なら、先にそのウィンドウを閉じる）
2. 黒いウィンドウに出るアドレス（例: `http://192.168.11.51:5180`）をスマホのブラウザで開く

PCとスマホの両方で同時に開いて遊ぶこともできます（「CPUと対戦」ならそれぞれ別のゲーム、「部屋を作る」なら一緒に遊べます）。

### スマホでつながらないとき

- **Windowsのファイアウォール**: Node.js への接続が許可されていないと、スマホからつながりません。
  「Windows セキュリティ」→「ファイアウォールとネットワーク保護」→「ファイアウォールによるアプリケーションの許可」→「設定の変更」で、
  「Node.js JavaScript Runtime」の **プライベート** にチェックを入れてください（パブリックは入れないでください）。
- **ネットワークの種類**: PCがつないでいるWi-Fiが「パブリック ネットワーク」になっていると、上の許可が効きません。
  「設定」→「ネットワークとインターネット」→ 使っているWi-Fi の「プロパティ」で「プライベート ネットワーク」にしてください。
- **VPN**: VPN（NordVPN など）を使っていると、同じWi-Fi内でもつながらないことがあります。一時的に切るか、VPNの設定でLAN内の通信を許可してください。
- スマホがPCと同じWi-Fiにつながっているか（ゲスト用Wi-Fiや5G/2.4Gの別ネットワークになっていないか）も確認してください。

## みんなで遊ぶ（通信対戦）

同じWi-Fiにつないだ端末どうしで、1人1台で遊べます（2〜4人。足りない席はCPUが入ります）。

1. ホストになる人が、タイトル画面の「部屋を作る」を押す。5文字の **部屋コード** が出る
2. 他の人は、同じアプリを開いて部屋コードを入れ、「入る」を押す
3. 全員が待合室にそろったら、ホストが「ゲーム開始」を押す

- インターネットにもつながっている必要があります（最初の接続で PeerJS の公開仲介サーバーを使うため）。
- 手番の操作は1回60秒、カウンターの確認は10秒まで。過ぎるとCPUが代わりに操作します。
- 途中で通信が切れても、同じ画面（ブラウザのタブ）で部屋コードを入れ直すと、同じ席に戻れます。戻るまではCPUが代わりに操作します。
- **ホストは、ゲームが終わるまでアプリを開いたままにしてください。** ホストの画面を閉じたり、別のアプリに切り替えたりすると、全員のゲームが止まります（ホストの画面は、自動で消えないようにしてあります）。
- **ホストの画面が閉じてしまったとき**: ホストが同じ端末・同じブラウザでアプリを開き直し、タイトル画面の「前のゲームを再開する」を押すと、同じ部屋コードで続きから再開できます。
  - 参加者は、画面を開いたままにしておけば（最長10分）自動で戻ります。画面を閉じてしまった人は元の席に戻れず、CPUが代わりに操作します。
  - ホストがゲームを終えたり「部屋を閉じる」を押したりすると、保存は消えます。24時間たった保存も使えません。
  - 前の画面が別のタブに残っていると、再開できないことがあります。
- フリーWi-Fiやルーターの「ゲスト用Wi-Fi」では、端末どうしがつながらないことがあります。
- 1台のPCで動作を確かめるときは、ブラウザのタブを2つ開いて、片方で部屋を作り、もう片方で入ります。

## GitHub Pages で公開する

`main` ブランチに push すると、自動テストを通してから GitHub Pages に公開されます（`.github/workflows/deploy.yml`）。

最初に一度だけ、GitHub のリポジトリの **Settings → Pages → Build and deployment → Source** を「**GitHub Actions**」にしてください。
公開されたアドレス（例: `https://<ユーザー名>.github.io/<リポジトリ名>/`）を、遊ぶ人に伝えます。

## 開発

```bash
npm install
npm run dev         # 開発用サーバーを起動（http://localhost:5180）
npm test            # 自動テスト
npm run typecheck   # 型チェック
npm run simulate    # CPUどうしで1000ゲーム行い、バランスの目安を表示（例: npm run simulate -- 500 3）
```

## フォルダ構成

| フォルダ | 内容 |
|---|---|
| `src/core/` | ゲームのルール（描画・通信に依存しない） |
| `src/scenes/` | ボードとコマの描画（Phaser） |
| `src/ui/` | タイトル・待合室・手札・ボタン・確認画面などのHTMLのUI |
| `src/net/` | 通信対戦（ホスト・参加者の進行役、PeerJS での通信）。1人プレイも同じ進行役で動く |
| `src/ai/` | CPUの思考、自動対戦 |
| `src/data/` | カード・ボードのデータ（JSON） |
| `tests/` | 自動テスト |
| `scripts/` | シミュレーションなどの道具 |
